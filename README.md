# 视频工作台

本地运行的 Mac 桌面应用：数字人对口型、字幕识别与烧录、AI 配音、音频提取、视频转文字。所有处理都在本机完成，素材不上传。

## 启动

双击 `启动视频工作台.command`。第一次会自动安装依赖、构建界面。

开发时：

```bash
cd app && npm run dev
```

## 功能

| 页面 | 做什么 |
|---|---|
| 工作台 | 今日完成数、连续使用天数、快速上手 4 步、进行中/最近完成的任务 |
| 字幕烧录 | 拖入视频或文件夹 → 识别语音 → 按样式把字幕、标题、底部声明烧进视频；也可以只导出 SRT |
| 数字人口型 | 形象库（≤60 秒视频或照片）+ 分组任务（每个形象×每个音频 / 一一对应）+ 背景音乐 + 替换背景 + 自动字幕 + 清晰度 |
| AI 配音 | 豆包语音合成 2.0：95 个中文/英文音色（可试听、按男女和场景筛选），也能填自己的复刻音色 ID；语速、音量、音调、语气指令；文案按空行/每行/整篇切成多条，批量生成 MP3 + 同名 SRT；一键送去「数字人口型」。另有「音频生成 1.0」模式：一段提示词同时生成对白、配乐、音效（单条 ≤120 秒），可加最多 3 条参考音色/音频（提示词里用 @音频N 引用）或 1 张参考图片 |
| 音频提取 | 批量从视频/音频里取出第一条音轨：MP3、M4A（AAC）、WAV、FLAC，或「原始音轨」不转码直接复制；可选码率、采样率、单声道，可播放结果（原「转 MP3」，输出目录仍是「MP3输出」） |
| 转文字 | 视频/音频转 TXT，可同时导出 SRT，结果页一键复制 |
| 采集中心 | 粘贴快手分享链接或整段分享文案 → 自动找出链接 → 解析并下载（多 CDN 自动切换），文案另存 txt；可选下载后自动加入字幕烧录 |
| 发布到账号 | 连接本机小V猫（3.0.0+）的 MCP 接口：读账号列表、选发布工具、参数对照、分发方式（每条发所有账号 / 均分 / 一一对应）、发布间隔、定时；字幕烧录和数字人页面可「加入发布队列」 |
| 设置 | 各模块输出目录、文件名后缀、序号、识别语言/模型/每行字数、编码器/画质、并发数、环境检测 |

右侧「字幕与文案样式」面板（字幕烧录和数字人共用）：3 个基础样式 + 13 个花字模板、随机样式、字体/字号/颜色/描边/外描边/阴影/底框细调、可拖动位置的标题/声明/文案、滤镜（固定/随机）、另存为我的样式、应用到选中视频。

## Windows 版

GitHub 私有仓库 `dulala567/video-workbench` 的 Actions（`.github/workflows/windows.yml`）在 Windows 云电脑上打包：推送到 main 或在 Actions 页手动运行都会出一个 ZIP（Actions 运行页的 Artifacts 里下载，保留 30 天）。

- 打包时下载 Windows 版 ffmpeg（gyan.dev essentials）、whisper.cpp（`b5907` 的 OpenBLAS 版）、识别模型 `ggml-large-v3-turbo-q5_0.bin`（574MB）、思源黑体（Noto Sans SC，OFL 开源），放进安装包的 `resources/bin|models|fonts`。
- **带数字人**：打包时用 uv 装一份可搬动的 Python 3.11（python-build-standalone），装显卡版 PyTorch（`torch==2.8.0`，CUDA 12.8，含 CUDA 运行库，用户只需 NVIDIA 驱动）和 MuseTalk 依赖，删掉运行用不到的 `torch/include` 和 `.lib`；MuseTalk、RobustVideoMatting 代码固定到和 Mac 相同的提交；模型（MuseTalk 1.5、sd-vae、whisper-tiny、face-parse、人脸检测 s3fd/2DFAN4、RVM）下载后校验 SHA256，放进 `resources/engines`。人脸检测模型通过 `TORCH_HOME` 指到包内，运行时不联网。
- 数字人在 NVIDIA 显卡上跑；没有 NVIDIA 显卡会退回 CPU（非常慢），界面顶部状态点和「设置 → 检测环境」会提示。显卡检测用 `nvidia-smi`。
- 显卡要求：PyTorch 的 CUDA 12.8 版支持 RTX 20 系（Turing）及以上；GTX 10 系及更老的不支持（没核实，依据是 PyTorch 发布说明里 cu128 去掉了老架构）。8GB 的 RTX 3070 由使用者实际跑通过。
- 降显存（v0.1.1）：模型先在内存里转半精度再放进显卡（原版先全精度进显卡，加载瞬间多占 3GB 多）；人脸检测在长边缩到 960 的图上做、关键点仍在原图上算；分析完形象后 `empty_cache`；按剩余显存定每批帧数（≥6GB 16 帧，≥3.5GB 8 帧，否则 4 帧），显存不足时减半重试。Mac 上模拟过显存不足的重试；真实 NVIDIA 显卡上的显存占用没测，每条任务的 `.log` 里会记最高显存。
- Windows 的 NVIDIA 驱动在显存满时会用内存顶替显存（不报错，慢一个数量级），所以「显存不够」表现为极慢而不是失败；生成进度里显存剩余 <0.5GB 时会提示关掉其他占显卡的程序。
- 中文路径（v0.1.1）：whisper-cli（`b5907`）在 Windows 上读模型路径时按 UTF-8 转码，而命令行参数是系统编码，软件放在中文文件夹里就崩溃（退出码 3221226505）。现在把工作目录切到模型文件夹、只传文件名，音频走标准输入。云端自检改成在带中文和空格的文件夹里跑。
- 数字人进度（v0.1.1）：Windows 上 Python 输出行尾是 `\r\n`，原来的进度行正则匹配不上，任务一直显示「准备中」。
- 升级补丁：每次打包另出 `VideoWorkbench-patch-v<版本>.zip`（`resources/app.asar` + `resources/engines/lipsync_runner.py`，几 MB），覆盖到已解压的完整包里即可升级；Python 环境或模型有变化时补丁不够，要重新下完整包。
- 口型脚本的 Windows 适配：中间文件用 libx264 编码（Mac 用 VideoToolbox）；OpenCV 的 `imread/imwrite` 不认中文路径，换成读字节后解码；背景视频改用 ffmpeg 管道解码（`cv2.VideoCapture` 同样不认中文路径）。
- 字幕字体：Mac 字体在 Windows 上换成宋体/楷体/黑体或自带的思源黑体；字幕滤镜在临时目录里用相对路径，字体目录参数转义盘符冒号。
- 硬件编码：Windows 依次试 NVENC / QSV / AMF（真编一小段成功才用），否则 x264。
- 自检：`VideoWorkbench.exe --self-test <目录> --sample <中文语音>`，打包流程里在真机跑一遍（生成视频、两种样式烧录中文字幕、三种音频提取、中文识别、界面加载），结果和截图在 Artifacts 的 `selftest` 里。

## 技术说明

- **语音识别**：whisper.cpp（`whisper-cli`，Metal 加速）+ large-v3-turbo。识别结果按标点和「每行最多字数」切成短句，时间按字数比例分配。
- **字幕烧录**：生成 ASS 字幕交给 ffmpeg 的 libass 渲染；双描边花字用两层叠出来；中文超宽会自动折行。编码默认用 Apple 硬件编码（h264_videotoolbox）。
- **对口型**：MuseTalk 1.5。原版依赖的 mmpose 在 Mac 上难装，改用 face-alignment 的 68 点关键点；形象首次使用时分析人脸并缓存到形象库目录，之后直接读缓存；生成时逐帧送进 ffmpeg 编码。
- **替换背景**：RobustVideoMatting 抠出人像透明度（每个形象首次换背景时计算并缓存），再和背景图片/循环视频合成。
- **删除原文件**：所有「删除原视频」选项都是移到废纸篓，可以找回。
- **AI 配音（豆包）**：`POST https://openspeech.bytedance.com/api/v3/tts/unidirectional`，新版控制台 API Key 用 `X-Api-Key` 头，`X-Api-Resource-Id` 为 `seed-tts-2.0`（复刻音色 `S_` 开头时用 `seed-icl-2.0`）。返回是逐行 JSON（音频 base64 + 逐字时间戳，最后一行 `code 20000000`）。长文案按句切成 ≤280 字一段分别合成，ffmpeg 拼接，逐字时间戳按每段实际时长平移。每条配音旁边保存 `.words.json`，字幕烧录和数字人遇到它就直接用配音原文和逐字时间做字幕，不走语音识别。音色清单在 `app/shared/doubao-voices.json`（来自官方音色列表页）。API Key 用系统钥匙串加密保存。
- **音频生成 1.0（豆包 seed-audio-1.0）**：不在火山方舟上调用，走豆包语音的 `POST https://openspeech.bytedance.com/api/v3/tts/create`，同一个 `X-Api-Key`，请求体 `model: "seed-audio-1.0"`、`text_prompt`（≤3000 字）、`references`（`speaker` / `audio_data` / `image_data`）、`audio_config`（含 `enable_subtitle` 返回毫秒级逐字时间）。非流式，一次返回 base64 音频；生成可能要几分钟，所以用 Node `https` 发请求（自带 fetch 有 300 秒等响应头上限）。参考音频先用 ffmpeg 截成 30 秒内单声道 mp3。官方价按生成时长 1 元/分钟。
- **音频提取**：`-map 0:a:0` 取第一条音轨；「原始音轨」用 `-c:a copy`，按原编码选容器（aac→m4a、opus→opus、pcm→wav，其余 mka）。
- **采集**：用独立的持久会话（`persist:kuaishou`）请求分享页，读页面里的 `INIT_STATE` 拿视频直链。快手要求登录或验证时不会绕过，提示用户点「打开快手」在窗口里自己完成，cookie 留在这个会话里。
- **发布**：用官方 MCP SDK 连接 `127.0.0.1:3199`（往后试 4 个端口；依次试 `/mcp`、`/`、`/sse`），令牌用 `Authorization: Bearer` 传。小V猫没公开工具名和参数，所以连上后读工具列表，按名字和描述自动挑出账号工具和发布工具，按参数名自动对照字段（界面上可改，按工具名记住）。参数里账号是数组就一次调用，否则逐个账号调用。令牌用系统钥匙串（Electron safeStorage）加密保存。

| 转文字 | 18 秒中文语音 | 1.8 秒，逐词时间戳断句，导出 TXT + SRT |

| 替换背景·首次抠图 | 268 帧 | 7 秒 |

| 采集 | 1 条快手分享链接（130 秒，544×960） | 8 秒下载完 20.5MB；打开「自动烧录」后下载 + 识别 + 烧录共约 9 秒（第二次下载走了 CDN 缓存） |

发布功能**没有连真的小V猫测过**（这台 Mac 没装，官网也没公开 MCP 文档），工具名、参数格式、鉴权方式都是按常见做法兼容的；第一次连真机时，如果自动对照不对，在「参数对照」里手动选一次即可。

测试素材：MuseTalk 仓库自带的示例形象（yongen、sun，已加进形象库，可以删掉）和 macOS `say` 合成的中文语音。还没用真人实拍形象和真人录音测过。

## 已知限制

- Windows 版（含数字人）ZIP 约 7.8GB，其中数字人引擎约 8.8GB（解压后），显卡版 PyTorch 约 4.9GB。云电脑（4 核、无显卡）上用 CPU 跑 3 秒照片对口型 + 换背景用了 18.5 分钟（含加载模型和首次分析形象），能出片但没有实用价值，真实使用要靠 NVIDIA 显卡；显卡上的速度没实测。
- Windows 版只在 GitHub 的 Windows Server 云电脑上自检过，没在真实的 Windows 10/11 个人电脑上跑过；NVIDIA/Intel/AMD 硬件编码因为云电脑没有显卡，都没实测（检测失败会自动退回 CPU 编码）。云电脑上 18 秒中文语音识别用了 40 秒（4 核 CPU）。
- Windows 版没有微软代码签名，第一次打开会弹「Windows 已保护你的电脑」，要点「更多信息 → 仍要运行」。

- 豆包这个 API Key 目前只开通了**语音合成 2.0**（和声音复刻 2.0 的资源）。语音识别（录音文件识别标准版/极速版）都返回「requested resource not granted」，所以字幕识别仍用本机 whisper。在火山控制台开通「豆包录音文件识别」后可以再接上，中文识别会比 whisper 更准。

- 数字人生成速度在 Mac 上没有 NVIDIA 显卡快，见上方测试记录。
- 识别模型首次使用前需要下载（约 1.5GB）；数字人权重约 4GB。
- 采集目前只支持快手视频，图集作品会提示不支持。只下载你有权使用的作品。
- 花字的界面预览是用 CSS 近似的，和最终烧录效果会有细微差别，以成片为准。
